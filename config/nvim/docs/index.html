Features

Everything you need, nothing you don't.

Single Language Registry

Define a language once in lang_registry.lua — LSP, Mason, formatters and linters auto-wire from that entry.

14+ Themes & Ghostty Sync

Switch live with <leader>th. Your Ghostty terminal syncs automatically to whatever theme is active.

LeetCode + GitHub Auto-Sync

Solve problems natively. Every submission auto-commits and pushes to your GitHub repository.

Conform + Nvim-Lint

Async, non-blocking formatting and linting for every supported language, registry-driven.

Native Debugging

Full graphical debugger via nvim-dap for Python, Go and Rust.

Supermaven AI

Inline AI completions, paired with Snacks.nvim for fuzzy pickers, file tree, and terminal splits.

YouTube Background Player

Stream lofi or music in background with <leader>yp & HUD controls via <leader>yc.

Architecture

  
How NamiConfig is put together

  
A tour of how plugins, languages, user options and tools stay in one place without configuration sprawl.


  
1The Language Registry

  
The core design pattern lives at lua/core/lang_registry.lua. Classic Neovim setups split language config across separate files — LSP here, formatters there. NamiConfig unites all of it under one entry per language.


  

    

      lua/core/lang_registry.lua
      
    

    
-- Defining a language entry in M.langs
python = {
  lsp        = "pyright",
  mason      = { "black", "ruff", "debugpy" },
  formatters = { "black" },
  linters    = { "ruff" },
  lsp_opts   = { filetypes = { "python" } },
},

  


  
On load, this table is parsed to auto-configure four things: Mason dedupes and installs formatters/linters; lspconfig sets up the server and merges lsp_opts; Conform.nvim populates formatters_by_ft; nvim-lint wires linters into save autocommands.


  
2Directory Structure

  
Core settings stay isolated from plugin specs, so themes or options can change without touching code.


  
~/.config/nvim/
├── init.lua                    Loads options, lazy.nvim, settings, core settings
├── lazy-lock.json              Version lockfile tracking plugin commits
├── docs/                       This documentation site's source files
└── lua/
    ├── settings.lua            <-- Edit options here (theme, font size, transparent bg)
    ├── core/
    │   ├── lang_registry.lua   <-- Single source of truth for LSPs and formatters
    │   ├── keymaps.lua         Global keyboard shortcut declarations
    │   ├── autocmds.lua        Editor events (highlight on yank, format triggers)
    │   ├── options.lua         Standard vim options (line height, tabs, splits)
    │   └── settings_loader.lua Loader that reads and parses settings.lua
    └── plugins/
        ├── init.lua            <-- Plugin load matrix -- new plugins register here
        ├── ui/                 Visual elements: dropbar, lualine, bufferline, snacks
        ├── editor/              cmp completions, treesitter, comment, autopairs
        ├── lsp/                Mason package manager, cmp-lspconfig
        ├── git/                lazygit, diffview, gitsigns
        ├── ai/                 Supermaven autocomplete
        ├── formatting/         conform.nvim configuration
        ├── linting/            nvim-lint configuration
        ├── lang/               Per-language plugin specs (e.g. prisma.lua)
        └── extras/             Feature-toggle packs, loaded on demand


  

    

      
3Declarative Configuration

      
The primary interface is lua/settings.lua, exposing options in logical blocks:

      
return {
  ui = {
    theme       = "kanagawa-wave",
    transparent = false,
  },
  editor = {
    format_on_save = true,
    tab_size       = 2,
  },
  extras = {
    "plugins.extras.lang.go",
  },
}

    

    

      
4Dynamic Extras

      
Opt-in plugins live in lua/plugins/extras/, loaded only when named in settings.lua:

      
extras = {
  "plugins.extras.lang.rust",
  "plugins.extras.testing.neotest",
}

      
This keeps startup under 25ms — only the plugin suites your current work needs get loaded.

    

  


  
5Step-by-Step Guides

  

    

      
Adding support for a new language

      
    
        
  1. Open the registry at lua/core/lang_registry.lua.
    2. 
        
  2. Add an entry under M.langs for the filetype.
    3. 
        
  3. Specify the LSP server name (from lspconfig).
    4. 
        
  4. List Mason utilities — formatters, linters, debug adapters.
    5. 
        
  5. Add formatters/linters to trigger Conform/nvim-lint.
    6. 
        
  6. Save and launch — Mason installs the rest automatically.
    7. 
      

    

    

      
Registering a custom lazy.nvim plugin

      
    
        
  1. Create a new spec file under the matching lua/plugins/ category.
    2. 
        
  2. Write a standard lazy plugin table.
    3. 
        
  3. Required: import it from lua/plugins/init.lua.
    4. 
        
  4. Validate with the syntax-checking script.
    5. 
        
  5. Restart Neovim — lazy.nvim installs the new plugin.
    6.
